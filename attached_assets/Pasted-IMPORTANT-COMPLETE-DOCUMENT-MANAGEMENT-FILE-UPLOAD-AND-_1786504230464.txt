IMPORTANT — COMPLETE DOCUMENT MANAGEMENT, FILE UPLOAD, AND ADDITIONAL DOCUMENT REQUEST SYSTEM

أريد إضافة وتطوير نظام متكامل لإدارة المستندات والملفات داخل ABSHER TRAVEL، لأن النظام الحالي لا يوفر للموظف إمكانية طلب مستند إضافي من العميل، كما أن المستندات المرفوعة حالياً لا تظهر بشكل صحيح أحياناً ولا يمكن تنزيلها بسهولة من لوحة التحكم.

يجب تنفيذ هذا النظام بالكامل على:

1. ABSHER TRAVEL WEB PLATFORM
2. ABSHER TRAVEL MOBILE APPLICATION (iOS + Android)
3. ADMIN DASHBOARD
4. BACKEND API
5. EXISTING POSTGRESQL DATABASE
6. SECURE FILE STORAGE

IMPORTANT:
Web وMobile يجب أن يستخدموا نفس الـ Backend ونفس API ونفس PostgreSQL Database ونفس الملفات ونفس طلبات التأشيرات.

لا تقم بإنشاء نظام ملفات منفصل للويب والموبايل.

==================================================
1. إصلاح عرض المستندات الحالية داخل لوحة التحكم
==================================================

داخل:

Admin Dashboard
→ Visa Applications
→ Application Details

يجب أن تظهر جميع المستندات التي رفعها العميل بشكل واضح وصحيح، ومنها:

- Personal Photo
- Passport
- Residence
- Sponsor Residence
- European Residence / Visa
- Schengen Visa
- Any Required Document
- Any Additional Document Requested By Employee

المستند يجب أن يظهر كما رفعه العميل، وبجودة واضحة وأصلية قدر الإمكان.

لا أريد:

- صورة مكسورة
- صورة غير ظاهرة
- صورة مشوشة
- رابط منتهي الصلاحية
- رابط تقني يصعب على الموظف استخدامه
- ملف لا يمكن فتحه
- ملف يختفي بعد إعادة تحميل الصفحة

يجب أن يستطيع الموظف بسهولة:

- مشاهدة المستند
- فتح المستند بحجم كبير
- تكبير الصورة
- فتح الصورة في تبويب جديد
- تنزيل المستند
- مشاهدة الملف الأصلي بجودته الأصلية

يجب أن يكون هناك زر واضح:

"عرض المستند"

وزر:

"تنزيل المستند"

ويجب أن يكون تنزيل المستند مباشراً وسهلاً بدون أن يضطر الموظف إلى نسخ روابط أو التعامل مع Storage URLs.

==================================================
2. الملفات يجب أن تكون ملفات حقيقية
==================================================

جميع الملفات التي يرفعها العميل يجب أن تكون Real File Upload.

لا تعتمد على:

- Image URL فقط
- Base64 داخل قاعدة البيانات
- روابط مؤقتة
- روابط Frontend فقط

يجب رفع الملفات فعلياً إلى Secure File Storage.

ويتم حفظ مرجع الملف في PostgreSQL.

PostgreSQL يجب أن يخزن بيانات المستند والمرجع الخاص به، وليس محتوى الصور نفسها كـ Base64.

يجب التأكد من أن الملف:

- موجود فعلياً
- يمكن عرضه
- يمكن تنزيله
- مرتبط بالطلب الصحيح
- مرتبط بالعميل الصحيح
- لا يختفي بعد Refresh
- لا يختفي بعد Logout/Login
- لا يختفي بعد App Restart
- لا يختفي بعد Deployment

اسم المستند المطلوب:
[________________]

نوع الملف:

- صورة
- PDF
- صورة أو PDF

هل المستند إلزامي؟

YES / NO

ثم زر:

"إرسال طلب المستند"

6. رفع المستند من Web وMobile
==================================================

العميل يجب أن يستطيع رفع المستند من:

1. Web Platform
2. Mobile Application

بنفس الطريقة وبنفس النظام.

عند الضغط على:

"+ إرفاق المستند"

يتم فتح File Upload.

حسب نوع الملف الذي حدده الموظف:

إذا كان:

Image

يسمح برفع الصور.

إذا كان:

PDF

يسمح برفع PDF.

إذا كان:

Image or PDF

يسمح بالاثنين.

يجب التحقق من:

- نوع الملف
- حجم الملف
- سلامة الملف
- نجاح الرفع

بعد نجاح الرفع يجب ألا تظهر صورة مكسورة.

يجب عرض الملف الذي تم رفعه فعلياً.

"قام العميل برفع المستند المطلوب."

10. رفض المستند
==================================================

إذا كان المستند غير صحيح أو غير واضح:

الموظف يضغط:

"رفض المستند"

ويظهر حقل إلزامي:

"سبب الرفض"

مثال:

"الصورة غير واضحة، يرجى رفع كشف حساب أوضح."

بعد التأكيد تصبح حالة المستند:

"مرفوض — مطلوب إعادة الرفع"

ويصل إشعار للعميل:

"تم رفض المستند، يرجى إعادة رفعه."

مع عرض سبب الرفض.

ثم يظهر للعميل زر:

"إعادة رفع المستند"

ولا يتم إنشاء طلب جديد كل مرة.

يتم تحديث نفس Document Request مع الاحتفاظ بسجل الإصدارات السابقة.

11. حالات المستند
==================================================

كل مستند يجب أن تكون له حالة مستقلة عن Application Status.

الحالات المقترحة:

- Not Required
- Required
- Waiting for Customer
- Uploaded
- Under Review
- Approved
- Rejected
- Re-upload Required

يمكن استخدام أسماء عربية في الواجهة.

IMPORTANT:

لا تخلط:

Application Status

مع:

Document Status

مثال:

Application Status:
"قيد المراجعة"

Document Status:
"بانتظار العميل"

هذه حالتان منفصلتان.

==================================================
13. النظام يجب أن يكون Dynamic
==================================================

لا أريد أن تكون أسماء المستندات مكتوبة بشكل ثابت داخل الكود.

مثلاً لا تجعل:

"Bank Statement"

مكتوبة Hard-coded داخل التطبيق.

يجب أن يستطيع Super Admin من لوحة التحكم إنشاء مستند جديد في أي وقت.

مثال:

اليوم أريد:

"كشف حساب بنكي"

غداً أريد:

"شهادة راتب"

بعد شهر أريد:

"خطاب تعريف من العمل"

يجب أن أستطيع إضافة هذه المستندات من لوحة التحكم بدون تعديل الكود.

ويجب أن تظهر تلقائياً في Web وMobile حسب إعدادات التأشيرة.

==================================================
14. طلب مستند إضافي أثناء معالجة الطلب
==================================================

هذه نقطة مهمة جداً.

حتى لو لم يكن المستند موجوداً ضمن المستندات المطلوبة عند تقديم الطلب، يجب أن يستطيع الموظف طلب مستند جديد أثناء معالجة الطلب.

مثال:

العميل قدم طلب تأشيرة.

الموظف راجع الطلب.

الموظف يحتاج:

"كشف حساب بنكي لآخر 6 أشهر."

يقوم الموظف بالضغط:

"طلب مستند إضافي"

ثم يكتب:

اسم المستند:
كشف حساب بنكي

التعليمات:
يرجى إرفاق كشف حساب بنكي لآخر 6 أشهر.

ثم:

"إرسال طلب المستند"

يظهر الطلب فوراً عند العميل.

==================================================
18. الأمان والصلاحيات
==================================================

المستندات قد تكون حساسة جداً.

لذلك يجب عدم جعل الملفات عامة Public بدون حماية.

يجب استخدام Secure Storage Access.

المستخدم يستطيع الوصول فقط إلى مستنداته.

الموظف يستطيع الوصول فقط إلى المستندات التي تسمح له صلاحياته بمشاهدتها.

ويجب أن تتبع هذه الخاصية نظام Employee RBAC الموجود في النظام.

أضف صلاحيات مثل:

- View Documents
- Download Documents
- Request Additional Documents
- Review Documents
- Approve Documents
- Reject Documents

ولا يحصل الموظف تلقائياً على صلاحيات المستندات إلا إذا تم منحه الصلاحية.

==================================================
19. إصلاح الصور الحالية
==================================================

حالياً توجد مشكلة في لوحة التحكم حيث بعض المستندات تظهر بصورة مكسورة أو لا يمكن تنزيلها بشكل صحيح.

يجب إصلاح المشكلة من الأساس وليس فقط تعديل الواجهة.

يجب التأكد من:

Upload
→ Storage
→ Database Reference
→ API
→ Admin Dashboard
→ Web
→ Mobile

كلها تعمل بشكل صحيح.

أي ملف يرفعه العميل يجب أن يكون قابلاً للاسترجاع لاحقاً.

يجب ألا يعتمد النظام على Temporary URL ينتهي بسرعة.

إذا تم استخدام Signed URLs، يجب أن يتم توليدها بشكل آمن عند طلب العرض أو التنزيل.

20. تنزيل المستندات
==================================================

في Admin Dashboard يجب أن يكون هناك زر واضح:

"تنزيل"

عند الضغط عليه يبدأ تنزيل الملف مباشرة.

إذا كان:

JPG / JPEG / PNG

يتم تنزيل الصورة الأصلية.

إذا كان:

PDF

يتم تنزيل ملف PDF الأصلي.

لا أريد أن يقوم النظام بتحويل الصور إلى صور منخفضة الجودة.

ولا أريد أن يقوم الموظف بالضغط عدة مرات أو نسخ رابط حتى يستطيع تنزيل الملف.

25. المطلوب النهائي
==================================================

أريد نظام Document Management كامل وليس مجرد زر رفع ملف.

النظام يجب أن يسمح بـ:

1. رفع المستندات عند تقديم الطلب.
2. عرض المستندات للموظف.
3. تنزيل المستندات بسهولة.
4. عرض الصور بجودة أصلية وواضحة.
5. طلب مستند إضافي من الموظف.
6. ظهور طلب المستند فوراً عند العميل.
7. رفع المستند من Web.
8. رفع المستند من Mobile.
9. وصول المستند إلى Admin Dashboard مباشرة.
10. مراجعة المستند.
11. قبول المستند.
12. رفض المستند مع ذكر السبب.
13. إعادة رفع المستند.
14. حفظ إصدارات المستند.
15. إرسال إشعارات.
16. التحكم في أنواع المستندات من Admin Dashboard.
17. تحديد المستندات المطلوبة لكل Visa.
18. استخدام Secure File Storage.
19. حفظ بيانات المستندات في PostgreSQL.
20. تطبيق RBAC على المستندات.
21. استخدام نفس النظام والبيانات على Web وMobile.

- ترفع بنجاح

- يمكن تنزيلها

- يظهر للموظف
- يظهر بجودة واضحة
- يمكن تنزيله

TEST 3:
الموظف يطلب كشف حساب.

يجب أن:
- يظهر الطلب للعميل
- يصل إشعار
- يظهر زر Upload

TEST 4:
العميل يرفع كشف الحساب من Web.

يجب أن:
- يظهر للموظف فوراً
