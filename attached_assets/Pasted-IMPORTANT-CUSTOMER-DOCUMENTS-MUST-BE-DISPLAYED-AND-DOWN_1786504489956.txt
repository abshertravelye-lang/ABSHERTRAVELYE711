IMPORTANT — CUSTOMER DOCUMENTS MUST BE DISPLAYED AND DOWNLOADABLE CORRECTLY IN ADMIN DASHBOARD

There is a critical issue in the Admin Dashboard → Visa Applications → Application Details.

The customer uploads important documents such as:

1. Personal Photo
2. Passport Image
3. Residence ID
4. Sponsor Residence ID for Umrah applications
5. Any other documents required by the visa configuration

Currently, the Admin Dashboard shows the documents incorrectly or as broken/low-quality previews, and the Admin cannot easily download the original files.

THIS MUST BE FIXED COMPLETELY.

==================================================
1. ADMIN MUST SEE THE ACTUAL UPLOADED IMAGE
==================================================

When a customer uploads a document, the Admin Dashboard must display the ORIGINAL uploaded document/image.

Do NOT display:

- Broken image
- Missing image
- Low-quality thumbnail
- Blurry image
- Placeholder instead of the real image
- An incorrect file reference
- A temporary frontend preview that disappears

The Admin must see the actual file that was uploaded by the customer.

The image must remain available after:

- Page refresh
- Logout/Login
- App restart
- Server restart
- Deployment
- Opening the application from another device

==================================================
2. IMAGE QUALITY MUST BE PRESERVED
==================================================

Do NOT unnecessarily compress or reduce the resolution of:

- Passport images
- Personal photos
- Residence IDs
- Sponsor residence IDs
- Other official documents

The original uploaded file must be preserved.

If a thumbnail is used in the application list, it may be optimized for display, BUT:

When the Admin opens the document, the system must load the original/high-quality file.

The Admin must be able to clearly read passport information and official documents.

Do NOT destroy the original image quality during upload.

==================================================
3. VIEW DOCUMENT
==================================================

Each document inside:

Admin Dashboard
→ Visa Applications
→ Application Details

must have a clear button:

"View"

When clicked:

Open a proper document/image viewer.

For images:

- Display the full image
- Preserve aspect ratio
- Allow zoom in/out
- Allow the Admin to inspect the document clearly
- Allow opening the image in a larger/full-screen view where appropriate

The Admin should not have to struggle to inspect the document.

==================================================
4. DOWNLOAD ORIGINAL FILE
==================================================

Every uploaded document must have a clear:

"Download"

button.

Examples:

Personal Photo → Download
Passport → Download
Residence ID → Download
Sponsor Residence ID → Download

When the Admin clicks Download:

The system must download the ORIGINAL uploaded file.

Do NOT download:

- A screenshot of the preview
- A compressed thumbnail
- A broken file
- An HTML page
- A temporary frontend blob
- A low-resolution version

Download the actual stored file.

==================================================
5. EASY AND SIMPLE ADMIN EXPERIENCE
==================================================

The Admin should be able to do this easily:

Application Details
→ Documents
→ Click document
→ View full image
→ Download

The process must be simple and fast.

Do NOT require the Admin to:

- Copy URLs
- Open browser developer tools
- Find storage paths
- Copy file IDs
- Open complicated links
- Manually reconstruct file URLs

The Admin should have a normal:

"View"

and:

"Download"

button.

7. ORIGINAL FILE STORAGE
==================================================

The backend must store uploaded documents properly.

Each document must have a persistent reference linked to:

- User ID
- Application ID
- Document Type
- Original File Name
- MIME Type
- File Size
- Storage Path / Storage Key
- Upload Date
- Document Status

The database must store the reference to the actual stored file.

Do NOT store only a temporary browser URL.

Do NOT rely on:

blob:
URLs

for permanent document access.

The uploaded files must be stored in persistent storage.

==================================================
8. SECURE DOCUMENT ACCESS
==================================================

Documents contain sensitive customer information.

Do NOT make passport images, residence IDs, or personal documents publicly accessible.

The system must use authenticated and authorized access.

Only:

- Super Admin
- Authorized employees with the correct permission

should be able to view/download customer documents.

The document endpoint must verify:

1. User is authenticated
2. User has permission
3. User is authorized to access that application/document

A customer must NOT be able to access another customer's documents by changing an ID in the URL.

==================================================
9. EMPLOYEE PERMISSIONS
==================================================

Document access must respect the existing employee RBAC system.

Add/ensure permissions such as:

- View Customer Documents
- Download Customer Documents

Only employees who have the appropriate permission should see the View/Download actions.

For example:

Visa Employee may have permission to view passport and visa documents.

Other employees should not automatically receive access unless authorized by Super Admin.

==================================================
10. FILE TYPES
==================================================

Support common customer-uploaded document formats such as:

- JPG
- JPEG
- PNG
- WEBP
- PDF where applicable

For images:

Display the image viewer.

For PDF:

Display a PDF viewer or open the PDF securely.

The Download button must download the original file.

+
View Extracted Passport Data

==================================================
12. CUSTOMER UPLOAD → STORAGE → ADMIN
==================================================

The complete process must be:

Customer uploads document
→ Backend receives file
→ File is validated
→ File is stored in persistent storage
→ Database stores document metadata/reference
→ Application stores document relationship
→ Admin Dashboard retrieves authenticated document
→ Admin sees correct original document
→ Admin can View
→ Admin can Download Original File

This must work reliably.
