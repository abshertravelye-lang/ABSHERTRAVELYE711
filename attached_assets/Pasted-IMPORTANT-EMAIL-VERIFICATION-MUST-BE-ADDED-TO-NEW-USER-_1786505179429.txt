IMPORTANT — EMAIL VERIFICATION MUST BE ADDED TO NEW USER REGISTRATION

أريد إضافة نظام مصادقة وتفعيل البريد الإلكتروني عند إنشاء حساب جديد في منصة ABSHER TRAVEL.

هذه الخاصية مهمة وأساسية، ويجب تنفيذها بشكل احترافي وآمن على مستوى الواجهة الأمامية والـ Backend وقاعدة البيانات.

==================================================
1. التحقق من البريد الإلكتروني عند إنشاء حساب جديد
==================================================

عندما يقوم العميل بإنشاء حساب جديد في منصة ABSHER TRAVEL، يجب ألا يعتبر الحساب مفعلاً بشكل كامل إلا بعد التحقق من البريد الإلكتروني.

تسلسل التسجيل يكون كالتالي:

إنشاء حساب جديد
→ إدخال بيانات التسجيل
→ إرسال رمز تحقق إلى البريد الإلكتروني
→ ظهور صفحة إدخال رمز التحقق
→ العميل يدخل الرمز
→ Backend يتحقق من الرمز
→ تأكيد البريد الإلكتروني
→ تفعيل الحساب
→ الانتقال إلى المنصة/الملف الشخصي

لا تسمح للعميل بتجاوز خطوة التحقق.

==================================================
2. إرسال رمز التحقق إلى البريد الإلكتروني
==================================================

بعد أن يقوم العميل بإدخال بريده الإلكتروني وإكمال التسجيل، يجب أن يرسل النظام تلقائياً رمز تحقق OTP إلى البريد الإلكتروني الذي أدخله.

مثال:

رمز التحقق الخاص بك في ABSHER TRAVEL:

847291

ويجب أن يكون الرمز مؤقتاً وله مدة صلاحية محددة.

مثلاً:

صلاحية رمز التحقق: 10 دقائق.

بعد انتهاء المدة يجب أن يصبح الرمز غير صالح.

==================================================
3. تصميم رسالة البريد الإلكتروني
==================================================

أريد أن تكون رسالة البريد الإلكتروني احترافية جداً وليست رسالة نصية عادية.

يجب أن تحتوي الرسالة على:

- شعار ABSHER TRAVEL
- اسم المنصة
- تصميم احترافي ومتجاوب مع الجوال والكمبيوتر
- عنوان واضح
- رمز التحقق بشكل بارز
- مدة صلاحية الرمز
- رسالة توضح أن هذا الرمز يستخدم لتأكيد البريد الإلكتروني
- تنبيه أمني في حال لم يطلب العميل إنشاء الحساب
- اسم ABSHER TRAVEL في نهاية الرسالة

يجب أن يكون تصميم البريد الإلكتروني متوافقاً مع هوية ABSHER TRAVEL البصرية.

استخدم شعار المنصة الموجود في النظام، ولا تستخدم شعاراً عشوائياً.

مثال لمحتوى الرسالة:

----------------------------------------

ABSHER TRAVEL

مرحباً بك في ABSHER TRAVEL

لتأكيد بريدك الإلكتروني وإكمال إنشاء حسابك، يرجى استخدام رمز التحقق التالي:

        847291

رمز التحقق صالح لمدة 10 دقائق فقط.

إذا لم تقم بإنشاء حساب في ABSHER TRAVEL، يمكنك تجاهل هذه الرسالة.

هذه الرسالة آلية، يرجى عدم الرد عليها.

ABSHER TRAVEL
Your Trusted Travel Platform

----------------------------------------

أريد أن تكون الرسالة بتصميم Premium واحترافي، وليس مجرد نص عادي.

==================================================
4. صفحة إدخال رمز التحقق
==================================================

بعد التسجيل مباشرة، يتم نقل العميل إلى صفحة:

"تحقق من بريدك الإلكتروني"

ويظهر:

"تم إرسال رمز التحقق إلى بريدك الإلكتروني"

مع إظهار البريد بشكل جزئي لحماية الخصوصية.

مثال:

تم إرسال الرمز إلى:
ab****@gmail.com

ثم تظهر خانات إدخال رمز التحقق.

يفضل استخدام 6 خانات منفصلة:

[ _ ][ _ ][ _ ][ _ ][ _ ][ _ ]

مع انتقال المؤشر تلقائياً بين الخانات.

==================================================
5. زر إعادة إرسال الرمز
==================================================

يجب إضافة:

"إعادة إرسال الرمز"

ولكن لا تسمح بإرسال عدد غير محدود من الرموز بسرعة.

يجب وضع عداد زمني، مثال:

إعادة إرسال الرمز بعد 60 ثانية

وبعد انتهاء العداد يستطيع العميل طلب رمز جديد.

عند إرسال رمز جديد:

يجب إلغاء صلاحية الرمز السابق.

==================================================
6. التحقق من الرمز من خلال Backend
==================================================

مهم جداً:

لا يتم التحقق من الرمز في Frontend فقط.

يجب أن يتم التحقق من الرمز من خلال Backend.

التدفق:

Customer
→ Enter OTP
→ Backend API
→ Verify OTP
→ Check expiration
→ Check attempts
→ Confirm email
→ Activate account

لا تعتمد على JavaScript في المتصفح لتحديد أن الرمز صحيح.

==================================================
7. حماية رمز التحقق
==================================================

لا تقم بتخزين رمز OTP بشكل مكشوف في قاعدة البيانات إذا كان من الممكن تخزين Hash للرمز.

يجب تخزين:

- User ID
- Email
- OTP Hash
- Expiration Time
- Verification Status
- Number of Attempts
- Created At
- Verified At
- Last Resend Time

ويجب أن يكون هناك حد لمحاولات إدخال الرمز.

مثلاً:

بعد عدد معين من المحاولات الخاطئة يتم إلغاء الرمز الحالي ويجب إرسال رمز جديد.

==================================================
8. منع تجاوز التحقق
==================================================

مهم جداً:

لا تسمح للمستخدم بالوصول إلى وظائف الحساب التي تتطلب بريد إلكتروني موثق قبل إكمال التحقق.

مثلاً:

لا يستطيع التقديم على التأشيرات قبل:

Email Verified = TRUE

ويجب أن يكون ذلك مفروضاً من Backend وليس فقط من الواجهة.

لا تعتمد على إخفاء الأزرار في Frontend فقط.

إذا حاول المستخدم الوصول مباشرة إلى API أو رابط التقديم بدون التحقق:

Backend يجب أن يرفض العملية.

==================================================
9. حالة البريد الإلكتروني في قاعدة البيانات
==================================================

أضف إلى المستخدم:

email_verified

وتكون:

FALSE

عند إنشاء الحساب.

وبعد نجاح التحقق:

TRUE

ويتم تسجيل:

email_verified_at

بتاريخ ووقت التحقق.

==================================================
10. حالات الحساب
==================================================

يجب أن يدعم النظام حالات واضحة مثل:

Email Verification Pending
Email Verified
Verification Code Expired
Verification Failed
Verification Locked

والحالة الأساسية للمستخدم تكون واضحة في النظام.

==================================================
11. عند نجاح التحقق
==================================================

بعد إدخال الرمز الصحيح:

يظهر إشعار احترافي:

"تم التحقق من بريدك الإلكتروني بنجاح"

وبشكل أخضر مع علامة نجاح.

ثم يتم تفعيل الحساب.

مثال:

✓ تم التحقق من بريدك الإلكتروني بنجاح

مرحباً بك في ABSHER TRAVEL.

ثم يتم الانتقال إلى الخطوة التالية المناسبة، مثل:

إكمال الملف الشخصي.

==================================================
12. إذا كان الرمز خاطئاً
==================================================

إذا أدخل العميل رمزاً خاطئاً:

لا يتم تفعيل الحساب.

يظهر:

"رمز التحقق غير صحيح، يرجى المحاولة مرة أخرى."

مع احتساب محاولة التحقق.

==================================================
13. إذا انتهت صلاحية الرمز
==================================================

إذا انتهت صلاحية الرمز:

يظهر:

"انتهت صلاحية رمز التحقق. يرجى طلب رمز جديد."

مع زر:

"إرسال رمز جديد"

==================================================
14. إذا قام العميل بإغلاق الصفحة
==================================================

إذا أغلق العميل المتصفح أو التطبيق بعد التسجيل وقبل التحقق:

عند تسجيل الدخول مرة أخرى يجب أن يعرف النظام أن:

Email Verification = Pending

ويعيده إلى:

"تحقق من بريدك الإلكتروني"

ولا ينشئ حساباً جديداً مرة أخرى.

==================================================
15. منع إنشاء حسابات مكررة
==================================================

إذا كان البريد الإلكتروني مستخدماً بالفعل:

لا تسمح بإنشاء حساب آخر بنفس البريد.

إذا كان الحساب موجوداً ولكنه غير موثق:

يمكن إظهار خيار:

"إعادة إرسال رمز التحقق"

بدلاً من إنشاء حساب جديد.

==================================================
16. ربط النظام بالبريد الإلكتروني الحقيقي
==================================================

لا أريد نظاماً وهمياً أو رمزاً يظهر داخل النظام فقط.

يجب أن يصل رمز التحقق فعلياً إلى البريد الإلكتروني الخاص بالعميل.

استخدم Email Service حقيقية ومناسبة للإنتاج.

يجب أن تكون إعدادات البريد الإلكتروني محفوظة بشكل آمن في Server Secrets / Environment Variables.

لا تضع:

SMTP Password
API Keys
Email Secrets

داخل Frontend أو داخل الكود المكشوف.

==================================================
17. لوحة التحكم Admin Dashboard
==================================================

أريد أيضاً أن يستطيع Super Admin معرفة حالة البريد الإلكتروني للمستخدم.

في بيانات العميل يظهر:

Email:
example@gmail.com

Email Verification:
✓ Verified

أو:

⚠ Pending Verification

مع تاريخ التحقق:

Verified At:
YYYY-MM-DD HH:MM

==================================================
18. إعادة إرسال رمز التحقق من لوحة التحكم
==================================================

إذا كان مناسباً للنظام، أضف صلاحية للمسؤول المخول لإعادة إرسال رسالة التحقق للعميل.

لكن هذه الصلاحية يجب أن تكون محمية حسب نظام صلاحيات الموظفين الموجود في المنصة.

==================================================
19. الإشعارات
==================================================

بعد نجاح التحقق، يمكن أيضاً إظهار إشعار داخل المنصة:

"تم التحقق من بريدك الإلكتروني بنجاح."

ولا يتم إرسال إشعارات غير ضرورية.

==================================================
20. دعم Web + Mobile
==================================================

يجب أن تعمل مصادقة البريد الإلكتروني بنفس الطريقة على:

1. ABSHER TRAVEL Web Platform
2. ABSHER TRAVEL Mobile Application

ويجب أن يستخدم الاثنان:

نفس Backend
نفس API
نفس PostgreSQL Database
نفس User Accounts

لا تنشئ نظام تحقق منفصل للويب ونظاماً آخر للجوال.

إذا تحقق العميل من البريد من الجوال:

Email Verified = TRUE

ويجب أن يظهر الحساب موثقاً أيضاً في الويب.

وإذا تحقق من الويب:

يظهر موثقاً في التطبيق.

==================================================
21. الأمان
==================================================

يجب حماية النظام من:

- Brute Force OTP Attempts
- Spam Resend
- Multiple OTP Requests
- Expired OTP
- Reuse of Old OTP
- OTP Enumeration
- API Bypass
- Direct API Account Activation
- Duplicate Registration

ويجب استخدام:

Rate Limiting
Expiration
Attempt Limits
Server-side Validation
Secure Token/OTP Handling

==================================================
22. اختبار الخاصية بالكامل
==================================================

اختبر السيناريوهات التالية:

TEST 1:

عميل جديد
→ إنشاء حساب
→ وصول البريد
→ إدخال الرمز الصحيح
→ نجاح التحقق
→ تفعيل الحساب

TEST 2:

إدخال رمز خاطئ
→ رفض الرمز

TEST 3:

إدخال رمز منتهي
→ رفض الرمز
→ طلب رمز جديد

TEST 4:

طلب إعادة إرسال الرمز
→ وصول رمز جديد
→ إلغاء الرمز القديم

TEST 5:

محاولات OTP كثيرة
→ تطبيق Rate Limit / Lock

TEST 6:

محاولة الوصول إلى API قبل التحقق
→ Backend يرفض العملية

TEST 7:

إغلاق المتصفح قبل التحقق
→ تسجيل الدخول مرة أخرى
→ العودة إلى صفحة التحقق

TEST 8:

محاولة إنشاء حساب بنفس البريد
→ منع الحساب المكرر

TEST 9:

التحقق من Web
→ ظهور الحساب Verified في Mobile

TEST 10:

التحقق من Mobile
→ ظهور الحساب Verified في Web
